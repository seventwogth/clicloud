# clicloud v0.1.1

The client can now tell you when a newer version is out, and fetch it where that
is its place to do. Three things the interface drew wrongly are fixed, and the
Black Metal themes of Ghostty are built in.

## Changes

### Updates

- The client can look for a newer release of itself. At its first start it asks,
  in a window of its own, whether it may, and keeps the answer; `y` and `n`
  answer it. Until it is answered nothing about the client leaves the machine.
- A look happens at most once a day and goes through the same proxy as
  everything else. It is one request for the `SHA256SUMS` of the latest release:
  the names in that file carry the version, and its sums guard the download that
  may follow. Nothing is downloaded by a look.
- Two rows in the settings: **Updates**, whether to look, and **Version**, what
  this build is and what the look found. `Enter` on Version looks, or takes the
  release it found.
- Only a client installed from a release replaces itself. One installed by a
  package manager, or built with `cargo build`, says so instead of offering the
  update: a binary that overwrote itself behind a package manager's back would
  leave its database describing a file that is no longer there.
- An update is checked against the sum published for it before anything in the
  archive is unpacked, and the running binary stays in place until the new one is
  ready, so a download that fails half way leaves the client as it was. The new
  version runs from the next start.
- New settings: `update_check`, absent until the question is answered, and
  `update_checked`, the time of the last look.

### Color schemes

- The eleven Black Metal themes of Ghostty are built in: Bathory, Burzum, Dark
  Funeral, Gorgoroth, Immortal, Khold, Marduk, Mayhem, Nile, Venom and the plain
  one. Built-in schemes go from 45 to 56. They were available before only where
  Ghostty itself was installed, which left Windows without them, as Ghostty has
  no build for it.

### Fixed

- The bar and the times of a track stood at almost the end from the first
  second, reading 1:10 / 1:11 of a track three minutes long. A track fed to mpv
  through a pipe has no end in sight, so what mpv called the length was only what
  it had demuxed. The length SoundCloud gives is used instead, and mpv is
  believed only where it sees the whole of a track. The same wrong length was
  also written into a track known by nothing but its link, and no longer is.
- A row of facts on the track tab longer than its column was cut where the
  column ended, in the middle of a word, which the tags of a track hit often. It
  runs on under itself now.
- Emoji are left out of everything the interface draws. Terminals disagree on how
  many cells one takes, and where their count and the client's differ, all that
  follows it on the line stands in the wrong place. They are dropped from remote
  metadata and turned away at the text inputs, so what is typed and what is shown
  stay the same.
- A track that SoundCloud hands out encrypted only is named as DRM-protected when
  it fails to play or to be stored, and is not counted among the three failures in
  a row that stop the queue; ten such tracks in a row still do.

### Packaging

- PKGBUILDs for `clicloud` and `clicloud-bin` are kept in `packaging/aur`.
- The release workflow builds with `CLICLOUD_RELEASE` set. Only a binary built
  that way updates itself; nothing else sets it.

## Updating from v0.1.0

v0.1.0 knows nothing of updates, so this one is installed by hand, the same way
v0.1.0 was: the commands in the READMEs below, or your package manager. From
v0.1.1 onwards a client installed from a release can take the next one itself,
once you have allowed it to look.

Settings, the library, the queue and the cache are carried over untouched. The
settings file gains its new keys when it is next written.

## Installation

Download the archive matching your system and verify it against `SHA256SUMS`.
Extract it and put `clicloud` (or `clicloud.exe`) on PATH. Install `mpv` and
`yt-dlp` separately, then run `clicloud doctor` followed by `clicloud`.
The archive includes English and Russian instructions and example settings.

macOS marks a downloaded binary as quarantined and refuses to start it; clear the
mark once with `xattr -d com.apple.quarantine clicloud`. The Windows binary needs
no Visual C++ redistributable.

| Archive target | System |
| --- | --- |
| x86_64-unknown-linux-gnu | Linux x86_64, glibc 2.35+ (Ubuntu 22.04+) |
| aarch64-apple-darwin | macOS on Apple Silicon |
| x86_64-apple-darwin | macOS on Intel |
| x86_64-pc-windows-msvc | Windows x86_64 |

Updating itself needs `tar`, which every supported system carries: Windows has
bsdtar in its system directory from Windows 10 onwards, and it is named outright
there, because the GNU tar that a shell such as Git Bash puts first on the path
cannot read a zip.

## Known limitations

clicloud is an independent project, not affiliated with SoundCloud or endorsed
by it. SoundCloud access depends on yt-dlp, network access and track availability.
Account login and two-way synchronization are not supported. Some tracks provide
only previews, and tracks handed out encrypted cannot be played at all. Media keys
through MPRIS are available only on Linux with mpv-mpris. The binaries are not
code-signed or notarized. Automated playback checks decode audio without an audio
device; they do not verify speaker output.
