# clicloud v0.1.2

The interface was gone over for what stands in the way of using it. A terminal
of 80×24 shows a list worth the name, the keys work while the Russian layout is
on, and what a key did can be taken back or stopped. Nothing about playback, the
cache or the network has changed.

## Changes

### On a small screen

- At 80×24 a list showed two tracks, and an empty one had no room for more than
  its first line. The empty lines of the main screen are left out there: six
  tracks show, and the player takes five lines instead of seven. On a taller
  screen the gaps come back one by one, once the list shows ten tracks; from 34
  lines up the screen looks as it did.
- The tab of the track gains the same lines, so its cover is 22×11 cells at
  80×24 instead of 18×9, and more of what is known of the track fits beside it.
- The settings window showed 13 of its 18 lines there with no sign of the rest.
  Its frame now says which line of how many is the current one, as the frame of
  a list does.

### Keys

- The keys of the interface work in the Russian layout. A search typed in
  Russian leaves that layout on, and `f`, `a`, `s`, `q` and the rest then did
  nothing. A key is now read by its place on the keyboard, so `а` is `f` and `й`
  is `q`; where a text is typed, a letter is the letter that came. `/` and `?`
  are other keys in that layout, `Shift+\` and `Shift+7`.
- `q` closes a window wherever one is open and ends the run on the main screen
  alone. In the settings and in the window of an error it used to quit, while in
  the list of schemes it closed the list.
- Enter is no longer a yes to the question about updates: `y` and `n` answer it,
  and `Esc` is still a no.
- A text that is typed has a cursor: `←`/`→`, `Home`/`End` and `Delete` work in
  the search, the filter of the library and the lines of the settings, and a
  text longer than its box moves under the cursor.
- Stepping the cache size down ends at 256 MB, where it used to arrive at no
  limit, the opposite of what was asked for. `Enter` on that row lifts the limit
  or sets the usual one again.
- The Updates row is switched by `←`/`→` like the other switches.

### Taken back and stopped

- `Ctrl+Z` takes back the last change of the favorites: a track that `f` added
  or removed, which returns to the place it had, or the whole list that `F`
  added. Pressed again, it takes back the one before, up to fifty of this run.
- `x` on a track that waits to be stored lets it go, and `X` lets all of them
  go; what is stored already stays. Until now a list queued with `D` could only
  be stopped by switching the cache off.
- In the queue the third button takes the selected track out of it, and
  `Backspace` does what `Delete` does, for keyboards without that key.

### What the interface says

- A search that found nothing says so and names the question, where the
  invitation to search stood before.
- An error of yt-dlp is told with what it most often means and what to do about
  it: a refusal by SoundCloud (403, 429), a page that is not there (404), a
  network that does not answer. The words of yt-dlp follow in full. The `search`
  and `import` commands say the same.
- The line of keys at the bottom follows the screen: the tab of the track and
  the queue have their own.
- The button that removes a track from the cache reads "Unstore" in English and
  "保存解除" in Japanese. It read "Remove", which in the queue looked like
  taking a track out of the queue.
- The messages of `f` speak of the favorites rather than of the library, where
  a stored track stays after it has stopped being a favorite.
- A list that is being stored reports once, at its end, how many tracks it
  stored, rather than after every track over whatever else was being said.

## Updating from v0.1.1

A client installed from a release takes this one itself: open the settings
(`o`), go to the Version row and press `Enter` to look, and `Enter` again to
take what was found. It asks nothing of the network unless looking was allowed
or that key was pressed. One from a package manager is updated by it, and one
built with `cargo build` by building again.

Settings, the library, the queue and the cache are carried over untouched, and
the settings file has no new keys. Three habits change: `q` in the settings
closes them instead of quitting, Enter does not answer the question about
updates, and the cache size is freed of its limit with `Enter` rather than by
stepping below 256 MB.

## Installation

Download the archive matching your system and verify it against `SHA256SUMS`.
Extract it and put `clicloud` (or `clicloud.exe`) on PATH. Install `mpv` and
`yt-dlp` separately, then run `clicloud doctor` followed by `clicloud`.
The archive includes English and Russian instructions and example settings.

macOS marks a downloaded binary as quarantined and refuses to start it; clear the
mark once with `xattr -d com.apple.quarantine clicloud`. The Windows binary needs
no Visual C++ redistributable.

| Archive target | System |
| --- | --- |
| x86_64-unknown-linux-gnu | Linux x86_64, glibc 2.35+ (Ubuntu 22.04+) |
| aarch64-apple-darwin | macOS on Apple Silicon |
| x86_64-apple-darwin | macOS on Intel |
| x86_64-pc-windows-msvc | Windows x86_64 |

Updating itself needs `tar`, which every supported system carries: Windows has
bsdtar in its system directory from Windows 10 onwards, and it is named outright
there, because the GNU tar that a shell such as Git Bash puts first on the path
cannot read a zip.

## Known limitations

clicloud is an independent project, not affiliated with SoundCloud or endorsed
by it. SoundCloud access depends on yt-dlp, network access and track availability.
Account login and two-way synchronization are not supported. Some tracks provide
only previews, and tracks handed out encrypted cannot be played at all. Media keys
through MPRIS are available only on Linux with mpv-mpris. The binaries are not
code-signed or notarized. Automated playback checks decode audio without an audio
device; they do not verify speaker output.
